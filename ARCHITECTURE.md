# Project Architecture

This document provides a high-level overview of the project architecture for the Lev-Boots RAG system.

## 1. Overview

This is a full-stack TypeScript project that implements a Retrieval-Augmented Generation (RAG) system. The project is structured as a monorepo with two main components:

-   **Frontend:** A React-based user interface for asking questions.
-   **Backend:** A Node.js server that implements the RAG pipeline.

The two components work together to provide a seamless experience for the user, allowing them to ask questions about Lev-Boots and receive answers generated by an LLM based on a knowledge base.

## 2. Frontend Architecture

The frontend is a single-page application (SPA) built with React and Vite.

-   **Framework:** [React](https://react.dev/)
-   **Build Tool:** [Vite](https://vitejs.dev/)
-   **UI Library:** [Mantine](https://mantine.dev/)
-   **State Management:** [MobX](https://mobx.js.org/)
-   **Routing:** [React Router](https://reactrouter.com/)

### Key Components

-   `public/src/App.tsx`: The root component that sets up the application's routing.
-   `public/src/components/Home.tsx`: The main user interface for the RAG system. It provides a text input for users to ask questions, sends the questions to the backend, and displays the generated answers.

### Communication with Backend

The frontend communicates with the backend via a RESTful API. The `vite.config.ts` file is configured to proxy requests from `/api` to the backend server running on `http://localhost:3000`.

## 3. Backend Architecture

The backend is a Node.js application built with Express. It is responsible for the entire RAG pipeline, from data loading and processing to answer generation.

-   **Framework:** [Node.js](https://nodejs.org/) with [Express](https://expressjs.com/)
-   **Database:** [PostgreSQL](https://www.postgresql.org/) with the [pgvector](https://github.com/pgvector/pgvector) extension for vector similarity search.
-   **ORM:** [Sequelize](https://sequelize.org/)

### Key Components

-   `server/server.ts`: The main entry point for the backend server. It initializes the database connection, sets up the Express application, and defines the API routes.
-   `server/routes/ragRoutes.ts`: Defines the API endpoints for the RAG system:
    -   `POST /api/load_data`: Triggers the data loading process.
    -   `POST /api/ask`: Receives a user's question and returns a generated answer.
-   `server/controllers/ragController.ts`: Handles the business logic for the API endpoints, calling the appropriate services to perform the required tasks.
-   `server/services/ragService.ts`: The core of the RAG system. It contains the main functions for loading data and answering questions.
-   `server/services/dataService.ts`: (Currently empty) Intended to contain the logic for fetching data from various sources (PDFs, articles, Slack API).
-   `server/services/llmService.ts`: (Currently empty) Intended to contain the logic for interacting with the Large Language Model (LLM) for embedding and answer generation.
-   `server/config/database.ts`: Configures the Sequelize connection to the PostgreSQL database and runs the database migrations upon server startup.
-   `server/models/KnowledgeBase.ts`: Defines the Sequelize model for the `knowledge_base` table, which stores the text chunks and their corresponding embeddings.
-   `server/migrations/`: Contains the Sequelize migrations for creating the `knowledge_base` table and enabling the `pgvector` extension in the database.

## 4. RAG Pipeline

The RAG pipeline is implemented in the backend and consists of two main processes:

### Data Loading

The data loading process is initiated by calling the `POST /api/load_data` endpoint, which triggers the `loadAllData` function in `ragService.ts`. This process involves:

1.  **Fetching Data:** Reading documents from various sources, including PDF files, online articles, and a simulated Slack API.
2.  **Chunking:** Splitting the documents into smaller, manageable chunks of text.
3.  **Embedding:** Converting each text chunk into a vector embedding using an LLM (e.g., Google Gemini).
4.  **Storing:** Saving the text chunks and their embeddings to the `knowledge_base` table in the PostgreSQL database.

### Answering Questions

The question-answering process is initiated by calling the `POST /api/ask` endpoint with a user's question. This triggers the `ask` function in `ragService.ts`, which performs the following steps:

1.  **Embedding the Question:** The user's question is converted into a vector embedding using the same LLM that was used for the data loading process.
2.  **Similarity Search:** A similarity search is performed on the `knowledge_base` table to find the text chunks with embeddings that are most similar to the question embedding.
3.  **Prompt Construction:** A prompt is constructed that includes the user's original question and the retrieved text chunks.
4.  **Answer Generation:** The prompt is sent to the LLM, which generates an answer based on the provided context.
5.  **Returning the Answer:** The generated answer is returned to the frontend to be displayed to the user.

## 5. Database

The project uses a PostgreSQL database with the `pgvector` extension to enable efficient vector similarity search.

-   **Table:** `knowledge_base`
-   **Columns:**
    -   `id`: Primary key.
    -   `content`: The text chunk.
    -   `embeddings_768`: A vector column for storing 768-dimensional embeddings.
    -   `embeddings_1536`: A vector column for storing 1536-dimensional embeddings.
    -   `createdAt`, `updatedAt`: Timestamps.

The database schema is managed through Sequelize migrations, which are run automatically when the server starts.
